# Notes

## Pillar 1

- **Keep:** distroless `static:nonroot` with a `CGO_ENABLED=0` static binary. Image `devops-app` (`linux/amd64`) is **19.9 MB** uncompressed in `docker image ls` and 4.74 MB compressed, runs as `65532`, and has no shell.
- **Broke:** pulling `golang:1.27` stalled on the same layers from both Docker Hub and `mirror.gcr.io`, while `curl` fetched those layers at about 10 MB/s, so the network was fine and Docker Desktop's pull engine was stuck. **Fixed:** restarting Docker Desktop; the pull then took 21 s.
- **Checked the failure path on purpose:** throwaway PR #1 (closed, not merged) first broke `TestHealth`. `Test` failed and the single `Build & Push` job of the time was skipped. After the revert, the image built with `push: false` and nothing reached GHCR (`captures/step-1-pr-test-fail.png`, `captures/step-1-pr-build-no-push.png`). **Keep:** prove the gates with a deliberate failure instead of trusting the YAML.
- **Publish only what was tested:** I split `Build & Push` into `Build` (build once, `make smoke`, Trivy image scan, SBOM) and `Publish`, which pushes that same image only if its image ID matches, then signs it with keyless cosign and attests provenance and the SBOM. A parallel `Security` job adds gitleaks over the full history and `trivy fs`. The first push created the GHCR package as private; after I set it to Public, an anonymous manifest request for `:latest` returns `200`, so Pillar 2 needs no image-pull secret. **Keep:** a rebuild in the push job could ship bytes nobody scanned.
- **Keep:** each version pin lives in one place per tool (`go.mod` → `setup-go` via `go-version-file`; golangci-lint `v2.14.0` in the `Makefile` and `ci.yml`). `make lint` refuses to run on a different golangci-lint version, so local and CI lint results can't drift.
